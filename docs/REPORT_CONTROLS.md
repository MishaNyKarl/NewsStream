# Полные отчёты и эксперименты с поиском

## Доступ к «Читать дальше»

Это функция подписки, а не базового аккаунта. В «Тарифах и кредитах» есть переключатель
«Полный отчёт» при создании/копировании тарифа и отдельная форма изменения функции существующего тарифа.
Изменение действует на всех его действующих подписчиков. Цена, срок, баланс и другие возможности сохраняются.
Изменения записываются в финансовый аудит. Финансовая роль и просмотр не могут менять доступ.

При миграции существующие тарифы с ненулевой ценой получают функцию. Существующие бесплатные тарифы
и базовый аккаунт остаются без неё; владелец может включить функцию и в бесплатном тарифе вручную.
Новый тариф получает ровно выбранное значение; цена сама по себе его не включает.
Истёкшая подписка теряет доступ. Роль администратора не обходит проверку тарифа.
Старые кнопки проверяют действующие права при нажатии, а новые карточки показывают замок при отсутствии доступа.
Сведения чужого пользователя и удалённые обновления не раскрываются. Краткие отчёты остаются доступны.

## Админка → «Отчёты и поиск»

Настройки общие для всех пользователей; сохраняются в БД и применяются без перезапуска.
Предпросмотр не сохраняет параметры, не вызывает LLM и не отправляет сообщения.
Есть сохранение с причиной, защита от устаревшей формы и возврат стандартных значений.

| Настройка | Диапазон | По умолчанию | Что меняет |
|---|---|---|---|
| Слов в кратком содержании | 20–300 | 120 | Бюджет резюме, фактов и причины; заголовки и ссылки отдельно. Резюме получает половину бюджета, факты — до 30%, причина — остальное. |
| Слов в подробном отчёте | 0–3000 | 0 | 0 показывает весь сохранённый текст по частям. Ненулевое значение сокращает представление с явной отметкой и ссылками. |
| Слов в строке ежедневного отчёта | 10–80 | 40 | Максимальный объём каждого показанного обновления. |
| Поисковых запросов | 1–6 | 6 | Максимум логических запросов одной новой проверки. Hybrid выполняет запрос к Bing и Google, поэтому сетевых обращений может быть вдвое больше. |
| Попыток чтения страниц | 1–12 | 10 | Максимум открываемых найденных страниц одной проверки. |
| Источников для модели | 1–6 | 6 | Максимум отобранных источников для анализа и проверки доказательств. Не больше числа попыток чтения. |
| Слов из статьи для модели | 0–1500 | 0 | Сокращение контекста каждого источника; 0 сохраняет стандартный предел 4500 символов. |

До первого сохранения поисковые лимиты берутся из runtime-конфигурации бота. После сохранения настройка БД
имеет приоритет. Админка показывает стандартные значения до первого сохранения; если лимиты окружения
отличаются, первая сохранённая конфигурация заменяет их. Во время одной проверки применяется один снимок
параметров, без изменения общего объекта Settings между конкурентными заданиями.

LLM получает указание длины резюме, а интерфейс дополнительно обрезает текст по словам. Это максимумы,
не гарантированное число слов. Ограничения схемы ответа и Telegram также ограничивают длину.
Изменение объёма подробного отчёта не переписывает сохранённые факты и не запускает поиск заново.
Пороги уверенности, новизны, доказательства и проверка цитат сохраняются. Большая глубина может увеличить
время и стоимость; слишком короткий контекст может не содержать нужных доказательств.

## Установка и проверка

Нужны миграции `0013_full_report_entitlement`, `0014_report_controls` и обновление bot/worker/admin.
`alembic upgrade head`; обычный main CI/CD выполняет это автоматически.

1. Базовый аккаунт: «Читать дальше» предлагает тариф и не показывает полный текст, в том числе со старой кнопки.
2. Действующая подписка с функцией: открывается отчёт; после выключения функции или истечения срока доступ закрывается.
3. Админка: поменять длину в предпросмотре, затем сохранить; проверить аудит и старую форму в другой вкладке.
4. Сократить поиск до 1 запроса, 2 страниц и 2 источников; следующая проверка должна соблюдать эти пределы.
5. Подробный отчёт: проверить лимит слов, отметку сокращения и ссылки; поставить 0 и получить весь сохранённый текст.
