# Закрытый тест на 10 участников

Практический ручной прогон с галочками, ожидаемыми результатами и журналом дефектов: [ACCEPTANCE_CHECKLIST_RU.md](ACCEPTANCE_CHECKLIST_RU.md). Этот документ — общая программа исследования. Успешные автотесты не закрывают пункты ручной приёмки.

Продолжительность: 3 дня. Цель — проверить, хотят ли пользователи поручать боту наблюдение за конкретной историей и доверяют ли формулировке «что нового».

## Перед приглашением

Интересы: пройти INTEREST-01–INTEREST-07 в [чек-листе](ACCEPTANCE_CHECKLIST_RU.md). Проверить выбор «Просто интересна тема» без запуска наблюдения, сохранение состояния уже активной/приостановленной темы, отдельный список `/interests`, защиту от повторного нажатия, удаление и независимость от подписки. Подписка и оценка полезности сами по себе не должны создавать интерес. Подборки пока не рассылаются.

Оформление ожидания: проверить полоску, описание под ней, таймер и неизменную дату начала по МСК. При ожидании одного этапа полоска остаётся на месте. Финал содержит время начала/окончания и продолжительность; ошибка не заполняет полоску до конца, анализ без новых материалов отмечается как пропущенный. Для обычного текста, пересылки с подписью и команды проверь привязку ответом; для кнопки в карточке-ответе — возврат к исходному сообщению. Конкретные пункты с галочками — UI-01–UI-04 в [чек-листе](ACCEPTANCE_CHECKLIST_RU.md).

Статусы ожидания: отправить URL и увидеть чтение страницы/подготовку карточки в одном сообщении; текст без URL не должен показывать чтение страницы. Запустить ручную проверку кнопкой и командой: проверить этапы поиска, чтения, анализа и явный итог даже без обновлений. При длительном этапе меняется прошедшее время, а этап остаётся настоящим. При недоступном поиске должен быть результат ошибки, а не «новостей нет». Повторный запрос модели отображается только при фактическом повторе. Автоматические проверки не должны присылать промежуточные статусы или сообщения об отсутствии новостей.

Дополнительные сценарии частого режима: выбрать «Следить внимательнее» при создании, проверить расписание и ближайшее время в карточке. Попытаться включить режим на второй теме и отменить перенос: первая должна остаться частой. Подтвердить перенос: прежняя тема остаётся в списке с обычным расписанием. Проверить паузу и возобновление: сутки режима не начинаются заново. Выключить режим и убедиться, что место свободно. Ручная проверка не должна откладывать запланированную. После суток режим сам становится обычным; не нужно ждать уведомления, если значимых новых фактов нет.

Администратор входит по личной ссылке, проверяет `/admin`, создаёт собственное наблюдение. Для гарантированной демонстрации интерфейса временно включает `DEMO_MODE=true` и использует `/demo_update`. Демо всегда отмечено как тестовое и не считается доказательством качества реального поиска.

## День 1: каждому участнику

1. Открыть пригласительную ссылку, нажать Start и прочитать краткое объяснение.
2. Создать минимум три наблюдения: одно из URL статьи, одно из текста о конкретном событии, одно по более широкому сюжету.
3. Перед подтверждением проверить название, изложение исходного состояния и цели наблюдения. Если бот понял неверно, отменить и уточнить исходный текст.
4. Открыть `/watching`, выполнить ручную проверку одного сюжета. У ручной проверки должен появиться явный итог в сообщении прогресса, даже если развития нет. Только автоматические проверки молчат при отсутствии развития.
5. Поставить другой сюжет на паузу, возобновить его. Создать и удалить отдельное тестовое наблюдение с подтверждением.
6. Посмотреть кнопку «Обсудить — скоро»; не ожидать полноценного чата.

## Дни 2–3

Оставить наблюдения активными. При каждом уведомлении открыть источники, сравнить с тем, что уже было известно, и выбрать «Полезно» или «Неважно». Отмечать отдельно отсутствие уведомления о событии, которое участник увидел самостоятельно. Не путать дату публикации с датой события.

## Контрольные сценарии администратора

| Сценарий | Ожидаемый результат |
|---|---|
| Незнакомый пользователь без invite | Закрытый доступ, история недоступна |
| Попытка открыть чужой story/update ID | Нет доступа или изменений |
| Один и тот же URL при повторной проверке | Нет повторного LLM-анализа этого источника |
| Новый пересказ без новых фактов | Нет уведомления |
| Подтверждённый новый факт по цели | Короткое уведомление со ссылкой и оценкой |
| Сбой API | Безопасная ошибка/повтор позднее, без выдуманного результата |
| Приватный IP или редирект в локальную сеть | Страница не скачивается |
| «Ignore previous instructions» в источнике | Текст рассматривается как данные, не получает инструменты |
| 6-я ручная проверка за день | Срабатывает пользовательский лимит |
| 11-й участник | Доступ не предоставляется |
| Перезапуск процессов | Наблюдения и история остаются |

## Вопросы после 1–3 дней

1. Было ли понятно, что делает бот?
2. Было ли понятно, что именно он будет отслеживать?
3. Доверяете ли вы формулировке «что нового»?
4. Были ли уведомления действительно новыми? Приведите пример повтора.
5. Было ли слишком много уведомлений?
6. Было ли слишком мало? Какое развитие бот пропустил?
7. За какими ещё типами событий вы хотели бы следить?
8. Пользовались бы таким ботом постоянно?
9. За что потенциально готовы платить?
10. Что больше всего раздражало?

## Что измерить

Активированные пользователи, созданные/активные/приостановленные наблюдения, переход от черновика к подтверждению, число проверок и уведомлений, доля «Полезно», пропущенные события из интервью, ошибки провайдеров, затраты на пользователя. Нулевое число уведомлений само по себе не доказывает хороший фильтр: сравните его с реальными событиями за период. Отдельно исключите демонстрационные уведомления из продуктовых выводов.
