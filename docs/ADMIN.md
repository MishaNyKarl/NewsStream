# Админка NewsStream

**Текущий сервер:** https://169.255.57.42:8443. Вход находится в отдельном закрытом файле доступа у владельца. Сертификат пока собственный, с SAN для IP; браузер предупреждает при первом открытии. Сверяйте SHA256 с файлом доступа.

Production обновляется через push в main — [CI/CD](CI_CD.md). Приведённые ниже Compose-команды предназначены для отдельной ручной установки; не пересобирайте работающий production в `:local`. Для применения изменённого runtime-окружения к активному образу: `python3 /opt/news-watch-bot/current/deploy/reload_settings.py admin`. [Чек-лист приёмки](ADMIN_ACCEPTANCE.md).

Отдельный процесс Starlette + серверный HTML, без frontend-сборки, обращения к LLM и изменений таблиц бота. Существующая PostgreSQL читается через `DATABASE_URL`. Сессии, настройки калькулятора, подтверждения и аудит хранятся в отдельном SQLite-томе. Публичного HTTP-входа нет: TLS завершается непосредственно в Uvicorn.

## Возможности и смысл данных

- Обзор БД, текущих очередей, ошибок, последней завершённой проверки, bot/worker/db и ресурсов хоста.
- Пользователи по последней активности, активные/приостановленные наблюдения и частый режим, события проверок и уведомлений.
- Расходы за даты, по пользователю и по каждому событию LLM, история провайдера/модели, альтернативная оценка по ставкам токенов.
- Калькулятор месячных расходов, безубыточной цены, цены с маржой и сценариев числа плательщиков. VPS и все остальные финансовые параметры вводятся владельцем; пустые значения не заменяются нулями.
- Текущие файлы `docs/*.md` в безопасном текстовом представлении, без исполнения HTML и произвольного доступа к файлам.
- Журнал входа/выхода, изменения расчётов, запроса перезапуска и результата. Один административный аккаунт; Telegram-администратор бота не является веб-администратором автоматически.
- Двухшаговый перезапуск только bot/worker, через отдельный host helper. Он необязателен для аналитики.

Период — от 1 до 366 дней, границы включительно по МСК; дневная сводка расходов явно обозначена UTC. В таблицах не более 50 строк на страницу; сводные суммы относятся ко всему отфильтрованному периоду. Фильтр пользователя применяется к очередям и расходам. Даты не применяются к текущему списку наблюдений, это указано в UI. «Активный пользователь» — `last_seen_at` в периоде, а не точная историческая DAU/MAU: история посещений не сохраняется. Наблюдения — тематические подписки, сведений об оплате в боте нет.

**Ограничение исходных данных о стоимости:** `app/ai/client.py` кладёт и provider `usage.cost`, и расчёт по ставкам в `usage_events.estimated_cost`. Признак происхождения/валюта не сохраняются. Поэтому записанная сумма показывается как непроверенная, подтверждённая стоимость — «нет данных». Альтернативная оценка по токенам не складывается с ней. При отсутствии токенов и записанной суммы результат неизвестен. Числа с нулевой суммой не доказывают бесплатность. Валюта старых записей предполагается USD и требует сверки. Историческая ставка могла отличаться от текущей.

Точную стоимость отдельной проверки восстановить нельзя: нет correlation ID, у первоначального анализа нет story_id, проверки могут пересекаться, после удаления темы часть связей обезличена. Отдельные строки `llm` — ответы/попытки модели; `check` и `story_check_completed` не являются независимыми проверками. Страница показывает длительность только там, где она записана. Для будущей точной бухгалтерии в основном приложении нужны `cost_source`, `currency`, nullable `actual_cost`, `request/check_id`, запись каждого биллингового результата и миграция. Админка не придумывает эти данные и не меняет исходный код бота.

## Файлы и требования

- `app/admin/`: веб-приложение, безопасные запросы, калькулятор, шаблоны и CSS.
- `requirements-admin.txt`: закреплённые прямые и транзитивные runtime-зависимости; не устанавливает aiogram/AI-клиент.
- `Dockerfile.admin`: сборка из корня репозитория, UID/GID 10001.
- `compose.admin.yaml`: отдельный проект `newswatch-admin`, внешний `newswatch_default`, без публикации PostgreSQL.
- `admin_ops/helper.py`, `install.sh`, systemd unit: ограниченный host helper.
- `admin_ops/env.example`: шаблон **отдельного** файла окружения.
- `tests/test_admin.py`: проверки входа, прав, CSRF, дат, расходов, математики, очередей, пагинации и перезапуска.

Python 3.12+, Docker Compose >= 2.30 (`env_file.format: raw` сохраняет `$` в Argon2-хеше), существующая схема бота вплоть до `0006_user_news`. Linux нужен только helper; приложение и автоматические тесты работают на Windows. Админка ограничена 256 МиБ и 0.5 CPU, helper — 128 МиБ. Один процесс Uvicorn и один одновременно выполняемый Argon2, до двух соединений PostgreSQL. Это лимиты, а не измеренное потребление сервера. Проверить запас RAM на сервере перед запуском.

## Переменные окружения приложения

| Переменная | Обязательность / значение |
|---|---|
| `DATABASE_URL` | Обязательна; существующий `postgresql+asyncpg://…@db:5432/…`. Никогда не выводится в UI. Можно использовать отдельную read-only роль на той же БД. |
| `ADMIN_ORIGIN` | Обязательна; точный HTTPS origin **без завершающего /**, например `https://169.255.57.42:8443`. Host и Origin форм проверяются. |
| `ADMIN_PASSWORD_HASH` | Обязательна; Argon2id, создаётся командой ниже. Простой пароль в окружение не кладётся. |
| `ADMIN_USERNAME` | По умолчанию `admin`. |
| `ADMIN_SESSION_SECONDS` | 28800 — абсолютный срок, не более 86400. |
| `ADMIN_IDLE_SECONDS` | 1800 — бездействие, от 300 до абсолютного срока. |
| `ADMIN_STATE_PATH` | `/data/admin.sqlite3`; Compose задаёт явно. |
| `ADMIN_DOCS_PATH` | `docs`; Compose задаёт `/app/docs` и монтирует актуальный каталог read-only. |
| `ADMIN_OPS_SOCKET` | Пусто — helper выключен. Для сервера `/run/newswatch-admin-ops/control.sock`. |
| `LLM_PROVIDER`, `LLM_MODEL` | Безопасный снимок конфигурации бота, не секрет. UI явно отличает его от исторических записей. |
| `ADMIN_LLM_KEY_FINGERPRINT` | Необязателен, только `sha256:` + 12 hex. Полный ключ отвергается. |
| `ADMIN_BOT_USERNAME` | Необязательное публичное имя бота, **не токен**. |
| `ADMIN_REVISION` | Необязательная ревизия сборки. |
| `ADMIN_BIND` | По умолчанию `127.0.0.1`; внутри контейнера `0.0.0.0`. |
| `ADMIN_PORT` | По умолчанию 8443; в контейнере всегда 8443. |
| `ADMIN_TLS_CERT`, `ADMIN_TLS_KEY` | Обязательны для запуска `python -m app.admin`; PEM сертификат и ключ. В Compose `/tls/server.crt`, `/tls/server.key`. |

Не передавайте `LLM_API_KEY`, `TELEGRAM_BOT_TOKEN`, `ADMIN_CLAIM_TOKEN`, пароль root или полный `.env` бота. Для отпечатка достаточно локально вычислить SHA256; это идентификатор ключа, не средство его восстановления.

Compose читает отдельные настройки из переменных **команды Compose**, а не из `admin.env`: `ADMIN_ENV_FILE` (default `/etc/newswatch-admin/admin.env`), `ADMIN_TLS_DIR` (`/etc/newswatch-admin/tls`), `ADMIN_DOCS_DIR` (`./docs`), `ADMIN_OPS_DIR` (`/run/newswatch-admin-ops`), `ADMIN_BIND_IP` (`127.0.0.1`), `ADMIN_PUBLISHED_PORT` (`8443`). Не используйте один файл одновременно как Compose `--env-file` и runtime `env_file`: интерполяция `$` может испортить хеш.

## Подготовка и локальный запуск

Из корня проекта, в отдельной venv (пример Linux; Windows использует `Scripts/python.exe`):

```sh
python3 -m venv work/admin-venv
work/admin-venv/bin/python -m pip install -r requirements-admin.txt
work/admin-venv/bin/python -m app.admin.password
work/admin-venv/bin/python -m app.admin.password --fingerprint
```

Пароль вводится интерактивно два раза, минимум 14 символов. Вторая команда принимает API-ключ через скрытый ввод и выводит только отпечаток; она не отправляет его по сети. Хеш копируется без кавычек в `ADMIN_PASSWORD_HASH` закрытого runtime-файла. При ручном `export` заключайте хеш в одинарные кавычки. Argon2id использует 64 МиБ, 3 прохода, параллелизм 1. Рекомендации библиотеки: [argon2-cffi](https://argon2-cffi.readthedocs.io/en/stable/howto.html).

Для локального приложения задайте переменные в окружении (они не читаются автоматически из `.env`), подключите собственную тестовую PostgreSQL или существующий тестовый SQLite `sqlite+aiosqlite:///…` и установите `aiosqlite==0.22.1` для SQLite. Само приложение **не создаёт таблицы бота** и не запускает polling. База для тестов создаётся фикстурами `tests/test_admin.py`. Локальный TLS-сертификат должен иметь SAN IP `127.0.0.1` или DNS `localhost`, соответствующий `ADMIN_ORIGIN`.

```sh
export ADMIN_ORIGIN=https://127.0.0.1:8443
export ADMIN_STATE_PATH=work/admin-state.sqlite3
export ADMIN_DOCS_PATH=docs
export ADMIN_TLS_CERT=/absolute/path/server.crt
export ADMIN_TLS_KEY=/absolute/path/server.key
# DATABASE_URL и ADMIN_PASSWORD_HASH уже заданы безопасным способом.
work/admin-venv/bin/python -m app.admin
```

Откройте `https://127.0.0.1:8443`. Для самоподписанного сертификата заранее проверьте SHA256-отпечаток и доверие; браузер может потребовать ручного решения владельца. Не отключайте проверку сертификатов глобально. HTTP отвергается даже при поддельном `X-Forwarded-Proto`; proxy headers выключены. Для reverse proxy используйте HTTPS upstream, сохраняйте Host и точный public Origin.

## Установка на существующий сервер

Эти шаги выполняет владелец основного развёртывания. Они не были выполнены этим чатом. Рабочий каталог приложения предположительно `/opt/news-watch-bot`; сверить с актуальным CI/CD.

1. Проверить `docker compose version`, сеть `newswatch_default`, контейнеры `newswatch-bot-1`, `newswatch-worker-1`, `newswatch-db-1` и labels `com.docker.compose.project=newswatch`, `com.docker.compose.service=bot|worker|db`. Проверить свободный порт 8443 и RAM. Не занимать чужой 443 и не менять существующие приложения.
2. Проверить, что UID/GID 10001 не принадлежит постороннему хостовому пользователю/сервису. Он предназначен для админки; при конфликте согласованно изменить Dockerfile, Compose-доступ к TLS, unit, проверку peer UID и владельца socket в helper. Не добавлять веб-пользователя в группу Docker.
3. Подготовить закрытый runtime-файл из `admin_ops/env.example`, заполнить действующий DATABASE_URL, хеш и безопасные сведения. Файл и каталоги остаются вне Git. Не выводить `docker compose config` с раскрытым окружением в общий лог.

```sh
install -d -m 0700 /etc/newswatch-admin
install -m 0600 admin_ops/env.example /etc/newswatch-admin/admin.env
# Заполнить файл защищённым редактором; пример значений в шаблоне не готов к запуску.
install -d -m 0750 -o root -g 10001 /etc/newswatch-admin/tls
openssl req -x509 -newkey rsa:3072 -sha256 -nodes -days 90 \
  -keyout /etc/newswatch-admin/tls/server.key \
  -out /etc/newswatch-admin/tls/server.crt \
  -subj '/CN=169.255.57.42' -addext 'subjectAltName=IP:169.255.57.42'
chown root:10001 /etc/newswatch-admin/tls/server.key /etc/newswatch-admin/tls/server.crt
chmod 0640 /etc/newswatch-admin/tls/server.key
chmod 0644 /etc/newswatch-admin/tls/server.crt
openssl x509 -in /etc/newswatch-admin/tls/server.crt -noout -fingerprint -sha256
```

TLS-каталог монтируется отдельно, поэтому родительский `/etc/newswatch-admin` может оставаться 0700. PEM-ключ должен читаться UID/GID 10001, но runtime env-файл доступен только root/Compose. Для домена используйте корректный сертификат доверенного CA с соответствующим SAN. Публичный URL нельзя объявлять доступным до проверки сертификата/маршрута.

4. После проверки кода установить **только helper**:

```sh
sh admin_ops/install.sh
```

Сценарий копирует два файла root-owned, создаёт группу для GID 10001, если её нет, включает и запускает/перезапускает только `newswatch-admin-ops.service`, не выполняет Docker restart. Каталог socket сохраняется при перезапуске helper, чтобы bind mount админки не указывал на старый inode. Unit запускается перед Docker при загрузке хоста: systemd создаёт runtime-каталог до восстановления контейнеров. Docker и helper должны быть включены в автозагрузку. Для работы без helper оставьте `ADMIN_OPS_SOCKET=` пустым и создайте пустой каталог `/run/newswatch-admin-ops` для обязательного bind mount (после перезагрузки нужно восстановить или задать постоянный пустой `ADMIN_OPS_DIR`).

5. Добавить `work/` в `.dockerignore` основным чатом, если ещё не добавлен. Dockerfile.admin копирует только нужные файлы, но отсутствие исключения отправляет локальные артефакты в build context. Затем из корня проекта:

```sh
docker compose -f compose.admin.yaml build admin
docker compose -f compose.admin.yaml up -d --wait admin
docker compose -f compose.admin.yaml ps
```

Это отдельный проект; команду запуска основного `compose.yaml` не выполнять. По умолчанию порт привязан к localhost хоста. Для публичного TLS-входа после проверки свободного порта и сетевых правил:

```sh
ADMIN_BIND_IP=0.0.0.0 ADMIN_PUBLISHED_PORT=8443 \
  docker compose -f compose.admin.yaml up -d --wait admin
```

`ADMIN_ORIGIN` должен совпадать с `https://169.255.57.42:8443`. Сетевое разрешение и конфигурация firewall остаются за основным развёртыванием: учесть, что Docker published ports могут обходить обычные UFW INPUT-правила; ограничение доступа задавать на внешнем firewall или подходящей Docker-цепочке. Проверить внешний доступ с разрешённого адреса, отсутствие HTTP-входа, login/CSRF, реальные данные. Не публиковать PostgreSQL.

Compose не монтирует Docker socket, код helper, runtime env-файл или файловую систему хоста в контейнер. Только TLS, docs, собственный том и каталог единственного Unix socket. Встроенный healthcheck проверяет исключительно веб-процесс, `healthz` не содержит внутренних сведений. Его loopback-проверка не проверяет публичное доверие сертификату.

Для дополнительной защиты создайте отдельную PostgreSQL-роль с `CONNECT`, `USAGE` схемы и `SELECT` только на `users, stories, story_updates, user_news, usage_events`; настройте её URL вместо общего. В приложении и с обычным URL включены `default_transaction_read_only=on`, `statement_timeout=7000`; однако отдельная роль сильнее защищает при компрометации самого процесса. Не менять credentials бота ради админки.

## Протокол helper и повторные операции

Локальный Unix socket `/run/newswatch-admin-ops/control.sock`, root:10001 0660, каталог 0750. Проверка Linux `SO_PEERCRED`: только UID 0 или 10001. Нет TCP, shell, произвольных аргументов, путей, имён контейнеров, чтения логов/Env или управления базой.

Один JSON + LF, до 1024 байт. Разрешены строго:

```json
{"action":"status"}
{"action":"restart","target":"bot","id":"f395e8bb-2dca-4ed3-a1fb-ec7d4efae591"}
```

`target` только `bot|worker`; `id` UUID v4, нижний регистр. Ответ — JSON + LF. Состояние содержит только статусы контейнеров, health/restart count, RAM, свободный диск, uptime/load и последние 10 операций. Docker inspect ограничен шаблоном, окружение и текст healthcheck не возвращаются. Перед restart сверяются имя, Compose labels и immutable container ID; выполняется фиксированное `/usr/bin/docker restart --time 20 <verified-ID>`.

Веб-подтверждение связано с сессией/целевым сервисом, действует 180 секунд, погашается атомарно перед вызовом helper. CSRF обязателен на обоих шагах; GET не перезапускает. Веб-журнал записывается до команды. Helper записывает UUID на диск до Docker-команды и повторно его не выполняет даже после рестарта helper. Между разными UUID на один сервис не меньше 120 секунд. `completed` означает завершение CLI restart, **не** успешную работу бота; нужно дождаться healthy.

`started` или `unknown` блокирует новые операции на тот же сервис до ручной проверки владельцем хоста, даже после 120 секунд. Это намеренно: timeout/обрыв не доказывает, что Docker не принял команду. Не удалять файл operations.sqlite3 ради повтора. После проверки Docker-состояния и журнала оператор может снять блокировку конкретной операции (с резервной копией ledger), отметив её `reviewed` через локальный SQLite; UI не имеет такой команды. Повтор того же UUID останется отказом от нового выполнения. Перезапуск веб-контейнера не перезапускает bot/worker.

## Безопасность, обновление и резервные копии

Cookie `__Host-newswatch-admin`: Secure, HttpOnly, SameSite=Strict, host-only, Path=/. Оpaque случайный токен, в SQLite только SHA256; токен меняется при успешном входе. Смена хеша/логина инвалидирует все сессии. Абсолютный и idle timeout серверные. Все POST проверяют точный Origin и CSRF, размер формы ограничен 8 КиБ, повторяющиеся поля отвергаются. Попыток входа не более 5 на IP и 25 глобально за 15 минут, сохраняются между рестартами. Учитываются и успешные попытки; режим консервативный, глобальный лимит может временно заблокировать владельца при атаке. `X-Forwarded-For` не используется. Пароль в access log не попадает, access log выключен. CSP запрещает скрипты/iframe-встраивание и сторонние ресурсы.

Ошибка БД не показывает connection string/SQL. Тексты ошибок допускаются только по безопасной грамматике; произвольные детали скрыты. Секретные конфиги/логи через UI не доступны. Docs монтируются из доверенного каталога, ссылки за его пределы отвергаются; дополнительная маскировка распространённых секретов не заменяет запрет хранить секреты в документации. Имена/темы пользователей — персональные данные, доступные только после входа.

Обновление только админки: `docker compose -f compose.admin.yaml up -d --build --wait admin`. Изменение docs видно через bind mount; смена TLS требует пересоздания/перезапуска только admin для перечитывания сертификата. Helper обновляется отдельно `install.sh`, bot/worker не трогаются. Не удалять том `newswatch-admin_admin_state`: в нём аудит и настройки. Для согласованной резервной копии SQLite используйте sqlite3 backup API, например через `docker compose -f compose.admin.yaml exec -T admin python ...`, либо остановите только admin на время копирования тома. Сохраняйте также root-only ledger `/var/lib/newswatch-admin-ops/operations.sqlite3`, runtime-файл и TLS-ключ в защищённом хранилище. Журнал не является криптографически неизменяемым и может быть изменён владельцем сервера/тома.

## Проверка

```sh
work/admin-venv/bin/python -m pip install pytest==8.4.2 pytest-asyncio==1.4.0 aiosqlite==0.22.1 httpx==0.28.1 ruff==0.16.9
work/admin-venv/bin/python -m pytest tests/test_admin.py -q
work/admin-venv/bin/python -m ruff check app/admin admin_ops/helper.py tests/test_admin.py
```

Тесты используют отдельную временную SQLite и подменяют только host/Docker-вызовы; реальный restart никогда не вызывают. Они проверяют атомарность SQLite admission/nonce/ledger и математические результаты, а не только ответы заглушек. Серверный smoke после настройки должен проверить реальную PostgreSQL, Linux peer credentials/права socket, ограничение read-only роли, TLS/SAN, Docker Compose build и memory limits. Подтверждённый restart — отдельная контролируемая операционная проверка владельца, не часть локального тестового прогона.
