# GitHub и автоматическое обновление

Репозиторий: https://github.com/MishaNyKarl/NewsStream. Рабочая ветка — `main`.

Репозиторий приватный. На текущем тарифе GitHub настройка защиты ветки для него недоступна (API возвращает 403 с требованием Pro). Прямые push разрешены; production обновляется только после успешных проверок workflow. Не используйте force-push.

Каждый push в `main` запускает `.github/workflows/ci-cd.yml`: проверку известных форматов секретов, Ruff, pytest с отдельной PostgreSQL 16, проверку архива и Compose. Только после успешных проверок конкретный коммит передаётся на сервер. Pull request запускает проверки без развёртывания. Ручной запуск доступен в Actions → NewsStream CI and deploy → Run workflow, ветка main.

## Устройство сервера

- Сервер: `169.255.57.42`, Ubuntu; проект: `/opt/news-watch-bot`.
- Исходники релиза: `releases/<полный SHA>`, активный релиз: ссылка `current`.
- Секреты бота остаются в `/opt/news-watch-bot/.env`; GitHub их не получает.
- Compose-проект: `newswatch`; контейнеры `newswatch-bot-1`, `newswatch-worker-1`, `newswatch-db-1`.
- Резервная копия PostgreSQL перед обновлением: `backups/deploy-<SHA>/database.dump`.
- Состояние и закрытый журнал: `deploy-state/<SHA>/status.json`, `deploy.log`.

Сначала собирается образ, пока текущий бот продолжает работать. После резервной копии выполняются миграции и проверка схемы. Затем обновление ждёт окончания активных проверок до трёх минут, заменяет bot/worker и проверяет их healthcheck. При замене возможен короткий перерыв; это не схема с нулевым простоем.

Обновление выполняет отдельная systemd-задача, поэтому обрыв SSH или остановка GitHub runner не оставляют бот специально выключенным. При ошибке возвращается предыдущий образ и каталог. ExecStopPost также пытается восстановить предыдущую версию при прерывании задачи. База автоматически назад не откатывается: миграции должны сохранять совместимость с предыдущей версией. Восстановление из дампа — отдельная ручная операция с оценкой новых данных.

## Доступ GitHub

Variables: `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_KNOWN_HOSTS`. Secret: `DEPLOY_SSH_KEY` — отдельный SSH-ключ пользователя `newsdeploy`. Проверка ключа сервера обязательна. Учётная запись принимает только `upload <SHA>`, `deploy <SHA>` и `status <SHA>`, не имеет Docker-группы и обычной командной оболочки по этому ключу. Загрузка проверяет пути, размеры, ссылки и манифест коммита.

Возможность менять код в main фактически даёт возможность запускать код приложения на production. Выдавайте write-доступ только доверенным участникам, защищайте GitHub-аккаунты двухфакторной аутентификацией. Проверка шаблонов секретов не заменяет просмотр diff.

## Обслуживание (root на сервере)

```sh
cat /opt/news-watch-bot/deploy-state/last.json
readlink /opt/news-watch-bot/current
docker ps --filter name=newswatch
# Подставьте SHA из Actions:
tail -n 100 /opt/news-watch-bot/deploy-state/SHA/deploy.log
systemctl status newswatch-deploy-SHA.service
```

Для отката к старому исходному коду сделайте `git revert` нужного коммита и push в main: он пройдёт те же проверки и создаст новый релиз. Повторный запуск уже успешно установленного SHA идемпотентен. Не редактируйте код непосредственно в `current`: следующий релиз берётся из GitHub.

## Первичная установка и изменение host-контроллера

Root-контроллер хранится отдельно: `/usr/local/lib/newswatch/deploy_remote.py`. Обновление файла `deploy/remote.py` в GitHub само по себе не меняет этот привилегированный контроллер. После проверки изменений администратор переносит `deploy/remote.py`, `deploy/install-host.sh` и публичный SSH-ключ в закрытый bootstrap-каталог и выполняет:

```sh
sh /opt/news-watch-bot/bootstrap-cicd/install-host.sh /opt/news-watch-bot/bootstrap-cicd/deploy.pub
```

Приватный ключ загружается только в GitHub Secret, не в репозиторий. После ротации необходимо обновить и authorized_keys, и Secret. Резервные копии сейчас локальные: регулярно переносите их на отдельное хранилище и контролируйте свободный диск. Старые релизы/дампы автоматически не удаляются.
