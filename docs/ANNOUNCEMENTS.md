# Оповещения пользователей

Раздел админки **«Оповещения»** (`/announcements`) предназначен для обновлений бота, изменений расписания и технических работ. Он не требует доступа к токену Telegram: админка сохраняет рассылку в PostgreSQL, а сообщения отправляет существующий worker.

1. Выберите шаблон: обновление бота, напоминание о времени отчёта или технические работы. Отредактируйте заголовок и обычный текст (до 2500 единиц UTF-16; эмодзи могут занимать две).
2. Выберите аудиторию: все зарегистрированные пользователи, пользователи с обычными подписками (включая паузу), ещё не выбравшие время отчёта, пользователи с активными наблюдениями или конкретные Telegram ID. Срочный режим с истёкшим сроком учитывается как обычный.
3. Выберите кнопку: выбор времени отчёта, главное меню или без кнопки.
4. Нажмите **«Предпросмотр и получатели»**. Это сохраняет черновик без отправки. Список получателей фиксируется в этот момент: новые пользователи не попадут в уже подготовленную рассылку.
5. При необходимости отправьте тест одному зарегистрированному пользователю. В сообщении будет пометка «Тест»; основная рассылка останется черновиком.
6. Нажмите **«Отправить N пользователям»**. Предпросмотр для первого запуска действует три минуты. Если он устарел, откройте страницу ещё раз. Повтор нажатия не создаёт второй рассылки.
7. Откройте результаты заново: видны доставленные сообщения, очередь, ошибки, недоступные боты, отмены и число попыток. Для каждого получателя указано выбранное время отчёта, если оно есть.

Создание, запуск, тест, отмена и повтор доступны владельцу и администратору панели. Роли «Просмотр» и «Финансы» могут только читать результаты. Все управляющие действия защищены сессией, проверкой Origin и CSRF, фиксируются в журнале админки. Запуск требует сохранённого предпросмотра с одноразовым подтверждением. Уже подготовленный текст не изменяется; кнопка **«Создать копию и отредактировать»** создаёт новый черновик.

Работает одна отправка оповещения за раз, включая несколько worker-процессов. Worker отправляет небольшие пакеты между обычными задачами, с ограничением времени пакета. Получатели, попытки и прогресс хранятся в БД. Временные ошибки повторяются с задержкой, максимум пять попыток; после этого доступны **«Повторить только ошибки»**. Доставленные сообщения и пользователи, заблокировавшие бота, при таком повторе не получают сообщение заново. `RetryAfter` Telegram приостанавливает всю очередь оповещений на заданный срок. Общая недоступность Telegram может также задержать другие сообщения бота.

**«Остановить рассылку»** отменяет ожидающие отправки. Уже начатая отправка может завершиться и отображается по фактическому результату. История сохраняется. Подписки не изменяются из-за ошибки или блокировки при рассылке оповещений.

Как и в остальных Telegram-outbox, при потере ответа после принятия сообщения Telegram возможен повтор: API не предоставляет ключ идемпотентности для `sendMessage`. Обычный перезапуск после подтверждённой доставки не повторяет отправленные сообщения.

## Переход существующих пользователей к ежедневному отчёту

Новости, подписки, паузы, срочные режимы и история сохраняются. Время не назначается без выбора пользователя. Для активной обычной подписки бот один раз предлагает выбрать время по Москве. До выбора времени ежедневный отчёт не отправляется; проверка новостей продолжает работать. Уже выбранное время не сбрасывается. Срочные подписки продолжают работу по прежней логике, затем переходят в ежедневный отчёт. Темы на паузе не отправляются до возобновления.

При подобных обновлениях используйте шаблон **«Обновление бота»** для общего объяснения. Для адресного напоминания используется шаблон **«Напомнить о времени отчёта»** и аудитория **«Ещё без времени отчёта»**. Напоминания не отправляются автоматически по кругу.

## Установка

Нужны миграция `0011_announcements` и обновление bot/worker/admin. Миграция создаёт `announcements` и `announcement_deliveries`, предоставляет роли `newswatch_admin` SELECT на настройки времени отчёта и ограниченные права INSERT/UPDATE на таблицы оповещений и их последовательности. Доступ к изменениям новостей, подписок и токену Telegram админке не добавляется.

## Ручная проверка

- Подготовьте сообщение со знаками `<`, `&` и эмодзи; проверьте текст в предпросмотре и тестовой доставке.
- Убедитесь, что черновик и повторное открытие не запускают рассылку.
- Отправьте тест себе, затем основную рассылку выбранным двум пользователям. Повторное нажатие не создаёт новых отправок.
- Проверьте аудиторию без времени отчёта до и после установки `/report`; темы на паузе остаются на паузе.
- Остановите рассылку: ожидающие получатели отменены, доставленные сохранены в истории.
- Проверьте просмотр и запрет управляющих действий для ролей «Просмотр» и «Финансы».
- После перезапуска worker проверьте продолжение очереди и отсутствие повтора подтверждённых доставок.
